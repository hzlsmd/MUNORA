# Free-tier hybrid AI recommendations

MUNORA combines deterministic weather/activity rules with supplementary text generated by Gemini. In Tips, expand **Plan My Activity**, choose an activity/time/duration, select **Check this plan**, then **Generate AI recommendation**. AI requests are explicit; opening the app, restoring a routine or running a background weather notification does not call Gemini.

The app continues working with rule-based advice before the AI service is connected, when offline, when weather is incomplete/outdated, or when either provider reaches its quota. The app never labels rule-based fallback as AI-generated. A real Gemini request requires the following account setup; fixture-based tests do not establish live model availability.

## Accounts and free-only setup

1. Create a project/key in [Google AI Studio](https://aistudio.google.com/apikey). Keep the Gemini API project on its **Free tier**; do not enable paid billing. Check your project's current available models and rate limits. Select a text model that supports `generateContent` and JSON `responseSchema` on the free tier. Google's [pricing](https://ai.google.dev/gemini-api/docs/pricing/) currently lists free text input/output for Flash-Lite models, including `gemini-2.5-flash-lite`; availability and retirement dates depend on the account and can change. MUNORA intentionally leaves the model unconfigured rather than silently choosing a paid model.
2. Create a [Cloudflare](https://dash.cloudflare.com/) account on **Workers Free**. The budget uses a SQLite Durable Object, supported on the free plan. Read [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/) and [Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/). Do not upgrade a plan to make the demo work; quotas should produce fallback.
3. Install Node 22+ and run the commands below. No key belongs in Dart, a `--dart-define`, git, a screenshot, or a chat message.

## Configure and deploy the gateway

From the repository root:

```sh
cd backend
npm ci
npm test
npm run check
npx wrangler login
npx wrangler secret put GEMINI_API_KEY
```

The last command prompts privately for your Google key. Restrict that key to the Generative Language API in Google Cloud where supported.

Edit `backend/wrangler.jsonc`:

- Set `GEMINI_MODEL` to the exact free-tier model ID available in your project, for example `gemini-2.5-flash-lite` if still available.
- Set `ALLOWED_ORIGINS` to your Flutter web site's exact origin. For multiple origins, use a comma-separated string, such as `https://munora.example,http://localhost:8080`. Android requests do not send a browser Origin and need no allowlist entry. Do not add `*`.
- Leave `DAILY_AI_LIMIT` at `100` or lower it to match your Google quota. It is a global application cap, shared by all users and all edge locations, not a promise of one hundred successful generations. Provider errors and invalid responses consume reserved calls.
- Leave `CLIENT_MINUTE_LIMIT` at `5` or lower it. Reservations use a one-minute bucket per hashed connection IP; users sharing a network share this limit.

Then:

```sh
npm run deploy
```

This creates one Worker and its budget Durable Object. Record the HTTPS `workers.dev` URL printed by Wrangler. No database, Firebase, user account system, Google Search grounding or paid add-on is needed. Do not deploy before your team is ready to share the service.

For local gateway development, copy your model/key into a git-ignored `backend/.dev.vars` file using a local editor, then `npm run dev`. Flutter deliberately requires an HTTPS endpoint; use a local HTTPS tunnel or a deployed test Worker for device/web end-to-end checks. Do not weaken HTTPS checks or embed the provider key to bypass setup.

## Connect Flutter

Install Flutter **3.47.9** (matching CI), then:

```sh
flutter pub get
flutter run --dart-define=AI_RECOMMENDATION_URL=https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev/recommendations
```

For the web build:

```sh
flutter build web --no-web-resources-cdn --dart-define=AI_RECOMMENDATION_URL=https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev/recommendations
```

For Android test builds use the same `--dart-define` with `flutter build apk --debug`. Production release signing remains governed by the existing release checklist. Endpoint defines are compile-time: rebuild after changing the URL. The Gemini secret stays only in Cloudflare.

## How the hybrid works

- Open-Meteo provides weather measurements. Full hourly condition readings are retained for rain/storm rules even though the forecast display uses three-hour samples. The cache version changes to avoid silently reusing older sampled-only hazard data.
- Flutter's existing rules assess the selected plan and remain visible beside AI advice. The Worker validates the weather/activity context and independently computes the window status and hazards before requesting supplementary advice. The selected hour inputs must all be complete; severe rule-only guidance still works with partial data.
- Gemini receives only allowlisted structured fields. It is asked for a short explanation and preparation actions, without invented measurements or official warning claims. Output has size/schema/content checks, including rejection of numeric measurements, URLs and common safety guarantees. These checks reduce errors; they cannot prove arbitrary generated language is correct. AI is labelled supplementary and never controls alerts or notifications.
- Advice expires after at most ten minutes, and earlier when the forecast becomes thirty minutes old, the current observation becomes three hours old, the insight hour changes, or the planned start arrives. Changing city, forecast, activity, start or duration discards displayed and pending results. No cached AI advice is shown offline from disk.
- Identical requests are cached in Flutter and at the Worker edge. The global Durable Object atomically reserves calls before Gemini, including across concurrent requests. Cache failures still allow bounded generation; budget failures fail closed.

## Privacy and abuse limits

The UI discloses sharing before the user taps Generate. The request contains city, activity, selected window, forecast timestamps, measured forecast inputs and hazard categories. It excludes names, exact GPS, saved routines, feedback, account IDs and free-text prompts. Google may use free-tier requests/responses to improve its products under its current [terms](https://ai.google.dev/gemini-api/terms). Do not send sensitive personal information. Cloudflare/Google still receive normal network metadata.

Application code does not log the key, prompt or generated text. Worker observability is disabled by default. The budget stores a SHA-256 hash of the connection IP and counts for the current day; the next reservation on a new UTC day overwrites it. Edge cache entries expire with the recommendation. CORS limits browser origins, but it is **not authentication**. The public endpoint can be called by other clients, who can exhaust the free daily cap; MUNORA then falls back. This is a deliberate capstone tradeoff. Rotate the secret if exposed; for a public launch add stronger abuse protection/account attestation and review privacy requirements.

## Verify before your defense

```sh
flutter analyze
flutter test
flutter build web --no-web-resources-cdn
cd backend
npm test
npm run check
```

On a real phone, test one successful generation, a rain/storm plan, a changed plan during generation, airplane mode, permission-independent weather notifications, and missing/quota-limited AI. Confirm hazards remain visible, no stale AI appears, and fallback wording is clear. Keep a screen recording of a real generation as a backup for unreliable venue internet; do not present fixture responses as live AI.

### Controlled browser regression

With Playwright and Chromium installed, build with the fixture-only endpoint below, serve `build/web` on port 8083, and run the smoke script:

```sh
flutter build web --no-web-resources-cdn --dart-define=AI_RECOMMENDATION_URL=https://munora-ai.test/recommendations
python3 -m http.server 8083 --bind 127.0.0.1 --directory build/web
# In another terminal, from the repository root:
node tools/check_ai_recommendations.cjs
```

The script intercepts weather and model requests and runs the real Worker handler on captured Flutter request bodies. It verifies explicit generation, storm guidance, successful AI text and quota fallback at mobile/desktop sizes. It is not live Gemini verification. Rebuild with your real Worker URL before giving the app to testers.
